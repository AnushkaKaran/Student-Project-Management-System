Que. Why we use formData in insert/update instead of multiple parameters
-> In backend insert and update functions we use only one parameter
called formData instead of multiple parameters.

Example:

async function insert(formData)

Here formData is an OBJECT which contains all the values
sent from frontend inside req.body.

When frontend sends POST request, it sends data in JSON format like:

{
  "ProjectGroupName": "AI Innovators",
  "ProjectTypeID": 1,
  "GuideStaffName": "Dr. Mehta",
  "ProjectTitle": "AI Chatbot",
  "ProjectArea": "Artificial Intelligence",
  "ProjectDescription": "Smart chatbot system",
  "AverageCPI": 8.5,
  "ConvenerStaffID": 2,
  "ExpertStaffID": 3,
  "Description": "Final year project"
}

This complete JSON object is received in backend as:

req.body

Service sends this req.body to model as:

model.insert(req.body)

So in model:

formData = req.body

Now formData becomes an object like:

formData.ProjectGroupName
formData.ProjectTypeID
formData.ProjectTitle
etc.

So instead of writing:

insert(name, typeId, guideName, title, area, description, cpi, convenerId, expertId)

We simply write:

insert(formData)

Advantages of using formData:

1. Easy to manage large number of fields.
2. No need to pass multiple parameters.
3. Dynamic handling of insert and update.
4. Clean and readable code.
5. Matches directly with frontend JSON data.
6. Useful for PATCH (partial update).

In SQL query we access values like:

'${formData.ProjectGroupName}'
'${formData.ProjectTypeID}'
etc.

So formData is nothing but a container (object)
which holds all form values sent from frontend.


IFNULL() [mysql built-in function]
-> IFNULL(value1,value2): If value is NOT NULL then use value1. If it is NULL use value2
for example: ProjectGroupName =
IFNULL(
  ${formData.ProjectGroupName ? `'${formData.ProjectGroupName}'` : null},
  ProjectGroupName
),
formData.ProjectGroupName ? :- checks if frontend has sent this field or not.If the value is sent for example
IFNULL('Veloura',ProjectGroupName), since veloura is not null database updates. If value is not sent like this
formData.ProjectGroupName = undefined then IFNULL(NULL,ProjectGroupName), so now first value is NULL so it will keep the OLD ProjectGroupName(no updates)
${} :- Run JavaScript code inside string.

-> For numeric fields :- IFNULL(${formData.ProjectTypeID ?? null}, ProjectTypeID)
In IFNULL() function, string values must be enclosed in single quotes (' ') 
while numeric values must not be enclosed in quotes. Using quotes with numeric 
foreign key columns may lead to constraint errors during update operations.

routes(folder)
->Why Router is Used in Express?

In Express.js, Router is used to divide and manage different API routes of the project into separate files.

If we do not use Router, then we have to write all API routes like:

app.get()
app.post()
app.patch()
app.delete()

inside a single file called index.js.

In a large project like SPMS, we have many modules such as:

Student
Staff
Project Group
Project Meeting
Project Type
Attendance

Each module contains multiple APIs like:

Get All
Get By ID
Insert
Update
Delete

So, if we write all these APIs in index.js, the file will become very large, complex, and difficult to read, understand, and maintain.

To solve this problem, Express provides Router.

Router allows us to create separate route files for each module such as:

student.route.js
staff.route.js
projectGroup.route.js
projectMeeting.route.js

This helps in organizing the project in a structured way.

Now, index.js becomes clean because it only connects these route files using: app.use()

Therefore, Router helps in:
Better code organization
Easy debugging
Improved readability
Proper separation of modules
Maintainable project structure
